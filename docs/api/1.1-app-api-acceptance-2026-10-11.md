## 1. 验收规则

每个接口的状态分开记录：

- `CODE_PRESENT`：找到运行时路由。
- `TEST_SOURCE_PRESENT`：找到对应自动化测试源；不等于本次已执行通过。
- `LOCAL_RUNTIME_EVIDENCE`：本地集成/运行时证据。
- `REMOTE_HTTP_EVIDENCE`：目标部署上真实 HTTP 请求、状态码、响应摘要及关联 ID。
- `ACCEPTED`：请求/响应契约、认证、权限、正负例测试和必要的远程证据全部满足。

当前审计工作站本身无法解析 `luckread.com`，因此没有从该工作站直接取得 API 响应；为取得真实请求证据，已由 GitHub Actions runner 执行线上烟测：[run 38085904460](https://github.com/wanghuinet/luckread/actions/runs/38085904460)，在提交 `9c99fa6f16f8d595be83e6442082d808b90ca79e` 上 **8/8 探针通过**。Artifact：`app-api-live-http-smoke-38085904460-1`，记录真实状态码、响应头中的 `cf-ray`、响应 JSON 顶层字段摘要和耗时，不保存原始响应正文或凭据。烟测只覆盖公开读取、无效输入和匿名拒绝；不覆盖有效账号成功登录/登出、已验证账号权限、成功创作、评论、点赞或关注写操作。部署工作流 [38039400765](https://github.com/wanghuinet/luckread/actions/runs/38039400765) 的构建/部署步骤成功，但它仍不能替代未覆盖接口的 E2E 证据。

## 3. 当前阻断项（按 APP 影响排序）

### APP-AUTH-01：登录契约与实际 Cookie 会话响应不一致 — P0

证据位置：
- `contracts/openapi/v1/openapi.yaml`：`authLogin` 要求 `identity`、`credential`、`deviceId`；成功 schema 声明 `accessToken`、`refreshToken`、`expiresIn`、`layer`。
- `workers/W01-payload/src/app/auth/login/route.ts`：只读取 `identity` 和 `credential`，忽略 `deviceId`，转发至 W02 的 `/sign-in/email` 并原样透传 Better Auth cookie/JSON。
- `workers/W01-payload/src/app/(frontend)/login/LoginForm.tsx` 与 `tests/int/login-frontend-v1.int.spec.ts`：前端使用 `credentials: 'include'`，没有携带 `deviceId`，也不读取 token DTO。
- `contracts/alignment/mapping-batches/AUTH-011-real-evidence-reconciliation.v1.md`：AUTH-011 刷新/轮换合同为 `BLOCKED_NOT_GREEN`，缺少 canonical refresh request/response 和有效凭据轮换证据。

影响：Android/iOS 客户端无法依据 OpenAPI 判断应当持有 Bearer token 还是 Better Auth session cookie；设备字段、登录层级和刷新语义也没有形成一个经过实测的稳定契约。

处理要求：先在变更控制中冻结唯一公共会话 wire contract，再同步 OpenAPI、DTO、W01 adapter、W02 会话语义和 APP 示例，并添加正/负向 HTTP E2E。**不能临时伪造 accessToken/refreshToken，也不能仅为了让接口 schema 通过而把 Better Auth 原始响应包装成无效 token。** 当前阶段不擅自改动认证语义。

验收条件：同一份真实成功登录响应同时满足冻结后的 DTO、会话持久化与权限层级；未验证邮箱、错误密码、撤销会话均有确定错误；APP 刷新/登出行为可重复测试。
