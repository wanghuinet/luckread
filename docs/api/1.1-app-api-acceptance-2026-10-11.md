- `CODE_PRESENT`：找到运行时路由。

## 3. 当前阻断项（按 APP 影响排序）

### APP-AUTH-01：登录契约与实际 Cookie 会话响应不一致 — P0

证据位置：
- `contracts/openapi/v1/openapi.yaml`：`authLogin` 要求 `identity`、`credential`、`deviceId`；成功 schema 声明 `accessToken`、`refreshToken`、`expiresIn`、`layer`。
- `workers/W01-payload/src/app/auth/login/route.ts`：只读取 `identity` 和 `credential`，忽略 `deviceId`，转发至 W02 的 `/sign-in/email` 并原样透传 Better Auth cookie/JSON。
- `workers/W01-payload/src/app/(frontend)/login/LoginForm.tsx` 与 `tests/int/login-frontend-v1.int.spec.ts`：前端使用 `credentials: 'include'`，没有携带 `deviceId`，也不读取 token DTO。
- `contracts/alignment/mapping-batches/AUTH-011-real-evidence-reconciliation.v1.md`：AUTH-011 刷新/轮换合同为 `BLOCKED_NOT_GREEN`，缺少 canonical refresh request/response 和有效凭据轮换证据。

影响：Android/iOS 客户端无法依据 OpenAPI 判断应当持有 Bearer token 还是 Better Auth session cookie；设备字段、登录层级和刷新语义也没有形成一个经过实测的稳定契约。

处理要求：先在变更控制中冻结唯一公共会话 wire contract，再同步 OpenAPI、DTO、W01 adapter、W02 会话语义和 APP 示例，并添加正/负向 HTTP E2E。**不能临时伪造 accessToken/refreshToken，也不能仅为了让接口 schema 通过而把 Better Auth 原始响应包装成无效 token。** 当前阶段不擅自改动认证语义。

验收条件：同一份真实成功登录响应同时满足冻结后的 DTO、会话持久化与权限层级；未验证邮箱、错误密码、撤销会话均有确定错误；APP 刷新/登出行为可重复测试。

### APP-AUTHZ-02：邮件验证后的 L1→L2 角色授予链路未闭合 — P0

证据位置：
- `workers/W02-identity/src/authz/role-assignment.ts` 的 `ensureBaseUserRole` 只写 `user` 全局角色；`contracts/authz/layers.json` 将 `user` 映射到 L1、`verified_user` 映射到 L2。
- `workers/W02-identity/src/auth/better-auth.ts` 的 `afterEmailVerification` 只调用 `activateVerifiedAccount`，没有调用 L2 角色授予逻辑。
- `workers/W05-social/src/index.ts` 的社交权限门拒绝缺少层级或低于 L2 的主体（403）。
- `contracts/entity/AUTHZ-role-assignment-authority.v1.json` 规定 RoleAssignment 是独立授权事实，必须由有授权且带审计来源的系统/管理动作记录；不得只用 emailVerified、accountState、Payload `User.role` 或客户端字段推断权限。

影响：新用户即使已完成邮箱验证并把 account state 变成 ACTIVE，现有代码也不能证明其已拥有有效的全局 `verified_user` RoleAssignment；点赞、关注、评论可能仍被 W05 拒绝。

处理要求：在既有 W02/D1-01 授权权威内补齐可审计的验证后角色授予/幂等/并发处理和撤销语义，绑定角色变更版本与缓存失效；不得在 W01 直接写 D1-01、不得只按 emailVerified 即时返回 L2，也不得直接给所有新用户授予 L3 creator。

验收条件：注册未验证= L1；成功验证后存在一条有效、可审计的 `verified_user` 全局 RoleAssignment= L2；重复回调不产生重复有效授权；L2 点赞/关注/评论成功；L1 同类写操作 403；客户端不能自行提权。

### APP-CONTENT-03：内容接口的公共 DTO 与实际 W03 响应尚未形成完整可复核矩阵 — P1

W01 的列表、详情、创建、修改、删除主要将请求转发给 W03 并透传响应。当前已确认路由和部分 adapter tests，但本次没有取得 W03 每一种内容类型（article/post/video）的线上完整请求/响应，也没有证明错误、游标、状态机、所有权拒绝与缓存失效的端到端行为。APP 应使用公共 DTO，而不能依赖 W03 内部字段或 Payload document shape。

处理：每种内容类型至少覆盖公开列表/详情、L3 新建草稿、本人修改、他人修改拒绝、发布/下线状态迁移、非法游标、ETag 冲突、幂等重放；将已脱敏响应样本绑定到 OpenAPI 示例和测试。未覆盖前状态保持 `PARTIAL`。
