## 1. Positioning

1.1 is the Mature Creator Core release.

Goal:
- make LuckRead a credible mainstream self-media creator platform;
- complete the creator operating loop without prematurely implementing the full 2.0 discovery/recommendation/live/marketplace stack;
- reuse Blueprint v2.0 Feature IDs and existing contracts;
- keep the locked 12 Worker / 4 D1 / 25 Task architecture unchanged.

Core loop:

Account
-> Creator
-> Draft/Edit
-> Article/Short Video
-> Review/Publish
-> Distribution
-> Follow/Like/Comment/Bookmark/Mention/Topic
-> Notification
-> Analytics
-> Subscription/Revenue
-> Rights/Safety/Appeal

## 5. Architecture / traffic guard

The locked architecture remains:
- 12 Workers;
- 4 D1;
- 25 Tasks.

No new Worker or D1 is introduced by 1.1.

Continue:
- public read cache-first;
- normal public read D1 reads = 0;
- cache miss D1 read <= 1;
- public read D1 writes = 0;
- authoritative mutation write transaction <= 1 where contract permits;
- derived writes asynchronous;
- single-flight cache misses;
- private responses not shared cached;
- rate limit before origin/D1;
- no direct frontend-to-D1 access.

Video bytes must not be routed through D1.
Media state is metadata; objects stay in object storage/CDN boundaries.

## 6. Development order

Wave 1: account + creator foundation
Wave 2: content production + article
Wave 3: media processing + short video
Wave 4: social graph + mention/hashtag/topic + notifications
Wave 5: analytics + SEO/distribution

Within each wave:
Blueprint -> Contract/Change Control -> Mapping -> Code -> Tests -> Runtime Evidence -> Reconciliation -> GREEN.

Existing valid evidence is not rerun merely for repetition.
