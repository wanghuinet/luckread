## 1. 威胁清单与防御（P0）

### 1.1 Authentication Bypass 认证绕过

- **防御：** 所有非公开端点必须有认证中间件；**默认拒绝**（deny-by-default）。
- **强制：** 路由白名单显式声明，新增路由默认受保护。
- **测试：** 未带 Token 访问每个受保护端点 → 401。

### 1.2 Authorization Bypass 授权绕过

- **防御：** 统一鉴权中间件；**禁止**在 handler 内散落 `if (user.role === 'admin')`。
- **强制：** 权限以 `resource.action` 表达（见 `docs/04-P0`）。
- **测试：** 低权限用户访问高权限端点 → 403。

### 1.3 IDOR 不安全的直接对象引用

- **防御：** 每次资源访问必须校验 `owner_id` / `org scope` / `visibility`。
- **强制：** 禁止仅凭 URL 中的 ID 返回资源。
- **强制：** ID 使用不可枚举格式（见 `docs/174`）。
- **测试：** 用户 A 用用户 B 的资源 ID 请求 → 404（**不得**返回 403 以 valid 存在性）。

> **注意：** 对无权限资源返回 **404** 而非 403，避免资源存在性泄漏。

### 1.4 Privilege Escalation 提权

- **防御：** 角色变更必须校验「授予者层级 > 被授予层级」且不得授予自身更高权限。
- **强制：** L7 不得授予 L8；L8 授予需双人审批（`docs/301` §3 L7/L8）。
- **测试：** 尝试自我提权 → 403 + 安全告警。

### 1.5 Cross-Tenant / Cross-Organization Access 跨租户

- **防御：** 所有查询强制带 `org scope` 或 `owner scope`。
- **强制：** 组织上下文来自 Token 解析的权威成员关系，**不得**来自请求参数。
- **测试：** T2（组织 A → 组织 B），见 `docs/302` §6。

### 1.6 Cache Poisoning 缓存投毒

- **防御：** 缓存 Key 包含完整主体维度（`docs/302` §3）；**禁止**用用户输入直接拼接 Key 而无校验。
- **强制：** 用户输入进入 Key 前必须规范化 + 长度限制 + 字符白名单。

### 1.7 Cache Leakage 缓存泄漏

- **防御：** `AUTHZ-CACHE-INVARIANT-001`（`docs/302`）。
- **强制：** 敏感操作 `cache_read = none`。

### 1.8 Replay Attack 重放

- **防御：** 写操作幂等 Key + `timestamp` + `nonce`；签名请求带时间窗（≤5 分钟）。
- **强制：** Webhook 签名必须含时间戳，超窗拒绝。
- **测试：** 重放旧请求 → 拒绝。

### 1.9 CSRF 跨站请求伪造

- **防御：** Cookie 使用 `SameSite=Lax/Strict`；状态变更请求要求自定义头（如 `X-Requested-With`）或 CSRF Token。
- **强制：** 若使用 Cookie 承载会话，必须实现 CSRF Token。
- **建议：** 优先使用 Bearer Token（不自动携带），从根本降低 CSRF 面。

### 1.10 XSS 跨站脚本

- **防御：** 所有用户内容输出转义；富文本使用白名单 sanitizer（Lexical 内容渲染必须 sanitize）。
- **强制：** 禁止 `dangerouslySetInnerHTML` 直出未 sanitize 的用户内容。
- **强制：** CSP 头配置。

### 1.11 SSRF 服务端请求伪造

- **防御：** 任何「用户输入 URL → 服务端请求」的功能必须：
  白名单域名 / 禁止内网 IP / 禁止 `169.254.169.254`（云元数据）/ 禁止重定向到内网 / 超时限制。
- **适用场景：** 媒体外链抓取、Open Graph 解析、Webhook 回调、导入功能。
- **强制：** 使用受控 fetch 封装，**禁止**直接使用用户 URL。

### 1.12 Injection 注入

- **防御：** D1 访问全部参数化查询；**禁止**字符串拼接 SQL。
- **强制：** 排序字段、过滤字段使用白名单枚举，**不得**直接拼接用户输入。
- **NoSQL/JSON：** 同样禁止把用户输入当查询结构。

### 1.13 Upload Abuse 上传滥用

- **防御：** 类型白名单（MIME + magic bytes 双重校验）、大小上限、频率限制、病毒/恶意扫描扩展点。
- **强制：** 校验**文件内容**而非仅扩展名或客户端声明的 MIME。
- **强制：** 上传对象默认私有，不直接暴露。

### 1.14 Malicious File 恶意文件

- **防御：** SVG 必须 sanitize（可含脚本）；禁止上传可执行文件；压缩包需检查条目数与解压体积（zip bomb）。
- **强制：** 文件处理在隔离环境；转码前校验。

### 1.15 Token Theft 令牌盗用

- **防御：** Token 短 TTL + Refresh Token 轮换 + 绑定设备指纹 + 异常登录检测。
- **强制：** 改密/登出/吊销 → `token_version` 递增 → 全部会话失效（`docs/302`）。
- **强制：** Token **不得**出现在 URL、日志、Referer。

### 1.16 Session Abuse 会话滥用

- **防御：** 会话列表可见、可单设备登出、可全部登出；并发会话策略可配置。
- **强制：** 异常地理位置/设备 → 二次验证或告警（`docs/72` §6–§7）。

### 1.17 Rate Abuse 限流滥用

- **防御：** 多维度限流（见 `docs/170`）：User / IP / Account / Org / API / Endpoint / Resource。
- **强制：** 匿名用户最严格；付费/企业用户配额更高。
- **强制：** 超限返回 `429` + `Retry-After`。

### 1.18 Bot Abuse 机器人滥用

- **防御：** 注册/登录/验证码接口必须有人机校验扩展点；设备指纹；行为分析。
- **强制：** 验证码接口本身必须限流（防短信轰炸）。

### 1.19 Enumeration 枚举

- **防御：** 登录/注册/找回密码**统一响应**（不区分「用户不存在」与「密码错误」）。
- **强制：** 资源不存在与无权限统一返回 404。
- **强制：** 验证码请求不泄露账号是否注册（或明确产品权衡）。
- **测试：** 批量探测账号 → 响应一致 + 触发限流。

### 1.20 Brute Force 暴力破解

- **防御：** 登录失败计数 + 指数退避 + 账户临时锁定 + IP 限流 + MFA。
- **强制：** 验证码尝试次数上限（默认 5 次）后失效。
- **强制：** 管理员/审核员（L5+）强制 MFA。

### 1.21 Webhook Forgery Webhook 伪造

- **防御：** HMAC 签名 + 时间戳窗 + 重放 nonce + 密钥轮换（`docs/169`）。
- **强制：** 验签失败 → 拒绝 + 告警。

## 2. 数据暴露红线

以下数据**禁止**出现在公开 API / 列表响应 / 日志中：

- 密码哈希、验证码、Token 明文
- 手机号/邮箱完整值（除非本人或已授权）
- 身份证/营业执照/实名信息
- 支付账户、对公账户
- 内部风控分数、封禁原因细节
- 审计报告内部备注
- 其他用户的私有内容

**强制：** DTO 必须显式白名单序列化字段，**禁止**直接序列化 ORM 实体。
