# LuckRead 1.0 → 2.0 文档归档与开发保护清单

**Status:** ACTIVE ARCHIVE GOVERNANCE

## Purpose

本清单定义 1.0 文档退出 `docs/` 活跃根目录的安全规则，确保 2.0 开发不会误读历史蓝图、重复审计或使用已被新 Canonical Source 替代的设计。

## 2.0 当前权威

1. `docs/00-LUCKREAD-ULTIMATE-FEATURE-BLUEPRINT-v2.0.md`：功能完整性唯一主清单。
2. `docs/300-ARCHITECTURE-BASELINE-WORKER-D1-R2-CACHE-MAP-v1.0.md`：架构边界权威。
3. `docs/301`–`307`：身份、授权、组织、并发、删除、安全等基础 Canonical Contract。
4. `docs/309-DOCUMENT-GOVERNANCE-AND-CANONICAL-INDEX-v1.0.md`：文档治理与 Canonical 解析。
5. `docs/312-BUILD-BASELINE-AND-BINDING-SEMANTICS-v1.0.md`：构建/绑定语义权威。
6. `contracts/`：机器可读契约；实现以当前 Contract/CI/Evidence 为准。
7. `docs/00-LUCKREAD-BLUEPRINT-ENHANCEMENT-*`：2.0 功能增强闭环，虽然文件版本号为 v1.0，但它们属于 2.0 增强层，不得因文件名含 v1.0 被归档。

## 归档规则

- 只归档已被 2.0 Canonical Source 明确替代的历史蓝图、审计、矩阵、Pass 报告和旧架构基线。
- 不按文件名中的 `v1.0` 自动删除；仍被 2.0 实现直接依赖的领域 Contract 保留。
- `contracts/`、D21 machine-readable assets、当前 API/OpenAPI、PAY、Rights、Safety、Data/Migration 等实现依据不得因版本号删除。
- 历史内容由 Git history 保留；本目录提供归档索引和原路径/Blob SHA 追踪。
- 删除后的旧路径不得重新作为实现依据；如需恢复，先经过 Canonical Source reconciliation。

## 本批归档范围

本批仅移除明确被 2.0 主蓝图/300+ Canonical Contract 替代的旧顶层蓝图、能力矩阵、审计和阶段性 Pass 文档。领域 Contract 暂不批量删除，以避免 2.0 实现阶段发生契约信息损失。

## 2.0 开发不变式

`Feature ID → Contract → Reuse/Refactor → Missing Implementation → Tests → CI → GitHub SHA → Evidence → Verified`

归档本身不改变 API、Data Model、Permission、State Machine、Event、PAY、Rights、Safety 或运行时代码。
