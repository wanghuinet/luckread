**Status:** P0 / CANONICAL
**Related:** `docs/160-DATA-LIFECYCLE-RETENTION-ERASURE-CONTRACT-v1.0.md`（保留/擦除策略，本文档补**删除语义术语与逐实体矩阵**）

## 0. 审计发现

| 检查项 | 全库命中 | 结论 |
|---|---|---|
| `Soft Delete` | **0** | ❌ 术语缺失 |
| `Hard Delete` | **0** | ❌ 术语缺失 |
| `Restore` | 32 | ⚠️ 零散，无统一语义 |
| `Tombstone` | 有（`docs/160` §8） | ✅ |

**结论：** `docs/160` 覆盖了保留/擦除/墓碑，但**没有**统一定义「软删除/硬删除」这对术语，
也没有**逐实体**的删除行为矩阵。这会导致每个开发者各写各的删除逻辑 → 数据不一致 + 合规风险。

## 1. 术语定义（Canonical）

| 术语 | 定义 | 可逆 | 可见性 |
|---|---|---|---|
| **Soft Delete** 软删除 | 标记 `deleted_at`，数据仍在库 | ✅ 可恢复 | 对全部 API 不可见 |
| **Hard Delete** 硬删除 | 物理删除行 | ❌ 不可恢复 | — |
| **Anonymize** 匿名化 | 保留记录结构，剥离个人身份信息 | ❌ 不可逆（身份层面） | 保留匿名内容 |
| **Tombstone** 墓碑 | 保留最小标识记录以维持引用完整性 | ❌ | 仅内部 |
| **Archive** 归档 | 业务下线保留（非删除） | ✅ | 不可见于公开列表 |
| **Erase** 擦除 | 合规删除（含派生数据、备份、缓存、索引） | ❌ | — |

### 1.1 规则

- **P0 默认：所有用户可感知实体默认 Soft Delete**，禁止默认 Hard Delete。
- Hard Delete 仅允许用于：临时数据、幂等记录、日志到期、法定留存期满后的擦除。
- **Soft Delete 后数据对全部 API 不可见**（包括 owner 自己），只能通过「回收站/恢复」接口访问。
- `deleted_at` 与 `deleted_by` 与 `delete_reason` 必须同时记录。

## 2. 删除层级

```text
L1 软删除（deleted_at）       —— 默认，可恢复
L2 匿名化（PII 剥离）          —— 内容保留，身份剥离
L3 墓碑（仅 ID + 类型 + 时间）  —— 引用完整性
L4 硬删除（物理行删除）         —— 需审批 + 审计
L5 擦除（含派生/备份/缓存/索引）—— 合规删除
```

**升级规则：** 只能沿 L1 → L5 单向升级；每次升级必须审计。

## 3. 逐实体删除矩阵（用户删除场景）

用户 `DELETED` 时，各实体的处理：

| 实体 | 默认层级 | 延迟 | 说明 |
|---|---|---|---|
| `User` | L2 → L3 | 冷静期后 30 天 | 先匿名化，再留墓碑维持引用 |
| `Identity` / `Credential` | **L4** | 立即 | 凭据立即硬删除（安全） |
| `Session` | **L4** | 立即 | 全部会话立即清除 |
| `Verification` | **L4** | 立即 | 验证码立即清除 |
| Content（已发布） | L2 | 冷静期后 | **匿名化作者**，内容保留（除非用户要求全部删除） |
| Content（草稿） | **L4** | 冷静期后 | 草稿直接删除 |
| `Revision` | **L4** | 随 Content | 草稿版本一并删除 |
| `Comment` | L2 | 冷静期后 | **匿名化**（保留上下文完整性） |
| `Like` / `Favorite` | **L4** | 冷静期后 | 关系型数据硬删除，计数异步修正 |
| `Follow` | **L4** | 冷静期后 | 硬删除，粉丝数异步修正 |
| `Block` / `Mute` | **L4** | 立即 | 立即清除 |
| `Media`（上传） | L2 → L4 | 冷静期后 | 被引用内容保留；未引用删除 R2 对象 |
| `Notification` | **L4** | 立即 | 立即清除 |
| `AuditEvent` | **保留** | 法定留存期 | **不得**因用户删除而删除（合规） |
| `Report` / `Appeal` | **保留** | 法定留存期 | 保留（合规 + 防滥用） |
| `Subscription` | L3 | 立即终止 | 停止续费，保留财务记录 |
| `Wallet` / `Ledger` | **保留** | 法定留存期 | 财务记录**必须**保留 |
| `OrgMembership` | **L4** | 立即 | 移除成员关系 |
| `IP`（principal） | **转移优先** | 冷静期 | 必须转移或解散，**不得**随用户删除 |
| Feed / Search 索引 | **移除** | ≤ 24h | 派生数据清除 |
| 缓存 | **失效** | ≤ 10s | 见 `docs/302` |

### 3.1 关键裁决

- **审计日志永不因用户删除而删除**（合规 + 安全）。见 ADR-D001。
- **财务账本永不因用户删除而删除**。
- **IP 不得随用户删除而消失**：必须转移给他人或按 `docs/304` §3.5 解散。
- **已发布评论匿名化而非删除**：删除会破坏讨论上下文，匿名化兼顾隐私与完整性。

## 4. 内容删除矩阵

| 内容状态 | 删除行为 | 子资源 | 索引 | 缓存 |
|---|---|---|---|---|
| `draft` | L4 硬删除 | 关联 Media 未引用则删 | 无 | 失效 |
| `pending_review` | L1 软删除 → L4 | 同上 | 移除 | 失效 |
| `published` | **L1 软删除**（默认） | 评论→L2 匿名化或隐藏 | **移除** | 失效 |
| `scheduled` | L4（取消定时） | — | 无 | 失效 |
| `archived` | L1 → L4 | — | 已移除 | 失效 |
| 已被引用的内容 | L1 + 警告 | **不得**级联删除被引用资源 | 移除 | 失效 |

**规则：**

- **禁止级联硬删除被其他内容引用的资源**（如被转载引用的 Media）。
- 内容删除后，Feed/Search **必须**在 ≤24h 内移除；缓存 ≤10s 失效。
- 内容删除**不删除** AuditEvent 与 ModerationCase。

## 5. 恢复（Restore）

| 场景 | 窗口 | 行为 |
|---|---|---|
| Soft Delete 内容恢复 | 默认 30 天 | 恢复为 `draft`（**不自动恢复为 published**） |
| 用户注销撤销 | 冷静期内（默认 15 天） | `DELETION_PENDING` → `ACTIVE`（见 `docs/303`） |
| 用户重新激活 | 注销后 30 天 | `DELETED` → `REACTIVATED` |
| 匿名化 / 硬删除 | **不可恢复** | — |

**规则：**

- 恢复**不保证**恢复原有分发位、推荐权重、粉丝关系。
- 恢复必须审计 + 发事件。
- 超过窗口的对象由 W08 作业推进到下一删除层级。

## 6. 保留期（引用 `docs/160`）

| 数据类 | 保留期 | 来源 |
|---|---|---|
| 审计日志 | ≥ 1 年（建议 3 年） | `docs/160` |
| 财务/账本 | 法定（≥ 5 年） | 法务 |
| 安全事件 | ≥ 1 年 | `docs/169` |
| 举报/申诉 | ≥ 1 年 | `docs/160` |
| 用户内容（活跃） | 直至删除 | — |
| 会话 | ≤ 30 天 | — |
| 幂等记录 | 24 小时 | `docs/305` |
| 验证码 | ≤ 10 分钟 | — |

## 7. 作业与幂等

- 删除推进由 **W08** 执行，必须幂等（`job_run_id`）。
- 删除作业**必须**先软删除再异步清理派生数据，**禁止**同步大范围级联删除。
- 每个删除层级推进必须写审计。

## 8. ADR

### ADR-D001 — 审计日志与财务账本不随用户删除而删除

- **Decision:** 用户删除只影响业务数据；审计与账本按法定留存期保留。
- **Reason:** 合规要求（可追溯、反欺诈、财务审计）；若随用户删除会导致审计链断裂。
- **Consequences:** 需实现「用户已删除但审计保留」的引用模型（墓碑 + 匿名 ID）。

### ADR-D002 — 默认软删除，硬删除需审批

- **Reason:** 硬删除不可逆，误删与恶意删除风险高。
- **Consequences:** 需要回收站/恢复窗口与 W08 清理作业。
