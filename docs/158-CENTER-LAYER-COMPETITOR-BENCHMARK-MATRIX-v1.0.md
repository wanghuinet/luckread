# LuckRead Center Layer Competitor Benchmark Matrix v1.0

**状态：BENCHMARK-CONTRACT-COMPLETE / CONTRACT-READY / IMPLEMENTATION PENDING**  
**范围：18 Center 的多平台最佳实践借鉴与 Superiority 基线**

## 1. Purpose

本合同把 18 Center 的竞品借鉴从原则变成可追踪矩阵。

借鉴对象包括：

```text
国内：今日头条 / 抖音 / 快手 / 微博 / 小红书 / B站
国际：YouTube / TikTok / X
```

平台被用于提取成熟能力、工作流、信息架构和体验原则，不复制品牌、视觉资产、专有文案、内部算法或内部实现。

## 2. Benchmark Rule

每个 Center 至少完成：

```text
Platform Pattern
→ Borrowed Capability
→ LuckRead Adaptation
→ Improvement Hypothesis
→ Metric
→ Acceptance Evidence
```

“参考某平台”但没有明确借鉴点 = INCOMPLETE。

## 4. Detailed Benchmark Dimensions

所有 Center 在实现前至少覆盖以下维度：

### 4.1 Information Architecture

检查：

```text
入口是否明确
核心任务是否集中
状态是否可见
关键动作是否就近
跨模块跳转是否保持上下文
```

### 4.2 Critical Journey

至少比较：

```text
创建
编辑
提交
等待
完成
失败
恢复
撤销
申诉
再次操作
```

### 4.3 Data Explanation

比较：

```text
数字
定义
时间范围
来源
新鲜度
变化原因
下一步动作
```

### 4.4 Error Recovery

比较：

```text
是否解释失败
是否保存进度
是否可重试
是否可继续
是否能避免重复提交
```

### 4.5 Permission / Privacy

比较：

```text
角色
scope
资源边界
敏感字段
团队协作
审计
```

### 4.6 Cross-device Continuity

比较：

```text
Web
Android
iOS
未完成任务
草稿
会话
操作状态
```

## 5. LuckRead Superiority Dimensions

LuckRead 不接受单项功能“比竞品多”作为 Superior 证明，而采用综合指标：

```text
Task Completion Efficiency
State Comprehension
Failure Recovery
Context Preservation
Permission Safety
Cross-device Continuity
Data Explainability
Performance
Cost
Observability
```

## 6. Required Comparison Evidence

每个高价值 Center 至少准备：

```text
1. Competitor baseline
2. Current LuckRead design
3. Difference
4. Metric definition
5. Target
6. Acceptance scenario
7. Evidence reference
```

证据可以来自公开产品文档、公开产品流程、实测记录、产品原型测试、性能测试或用户验收记录。

## 7. Anti-Copy Boundary

禁止：

- 复制竞品品牌身份；
- 复制竞品视觉资产；
- 复制专有文案；
- 逆向或依赖竞品内部实现；
- 将竞品 UI 作为 LuckRead 的唯一设计依据；
- 用“功能相似”冒充 Superior。

## 8. Benchmark Change Management

竞品平台持续变化，因此 Benchmark 不定义为永久不变事实。

当关键竞品能力发生重大变化时，应记录：

```text
benchmarkDate
platform
observedChange
affectedCenter
impact
adoptionDecision
reason
```

不得在没有重新验证的情况下声称“当前行业最佳”。
