# 一、绝对审计原则

必须严格执行以下规则：

### 1. Contract First，Code Next

唯一允许的开发顺序：

`Requirement → Contract → Machine-readable Contract → Validator → CI → Evidence → Admission → Implementation`

当前阶段优先审计：

> Contract → Machine-readable Contract → Validator → CI → Evidence → Admission

不要因为仓库现在能运行、文件存在、代码看起来合理，就判定 GREEN。

---

### 2. 零信任证据规则

以下状态一律不能算 PASS：

* UNKNOWN
* MISSING
* UNVERIFIED
* NOT_EXECUTED
* WRONG_SHA
* STALE
* SKIPPED
* TIMEOUT
* EMPTY_LOG
* NO_RUNNER
* continue-on-error
* workflow 未真正执行
* 只在本地通过
* 只做静态检查但没有 CI 证据
* 旧 SHA 的绿色结果
* 手工声称“已经通过”
* validator 没覆盖到的内容

只有：

> **当前 main SHA + 实际 GitHub Actions 执行 + 实际 steps + 实际 logs + 明确 conclusion=success**

才能作为 CI GREEN 证据。
