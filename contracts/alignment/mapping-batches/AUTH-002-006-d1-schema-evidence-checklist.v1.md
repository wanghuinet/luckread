# AUTH-002..006 D1 Schema Evidence Checklist v1

Status: CONTRACTED_NOT_VERIFIED / NOT_GREEN

## Purpose

This checklist defines the minimum executable evidence required before any AUTH-002 through AUTH-006 persistence mapping can be promoted from `PENDING_SCHEMA_EVIDENCE`.

## Required evidence per migration

1. Exact repository and branch/ref.
2. Exact tested commit SHA.
3. Exact D1 target/environment identity.
4. Pre-migration schema snapshot.
5. Migration identifier and ordered execution record.
6. Post-migration schema snapshot.
7. Actual table names and actual columns.
8. Actual types, nullability, defaults and foreign-key relationships where applicable.
9. Actual unique/index/constraint state.
10. Expected-vs-actual comparison generated by an executable check.
11. Migration result and exit status.
12. Runtime persistence test result against the same persistence target where required.
13. Security-negative result for secret/token/private-key non-persistence.
14. Evidence Registry record referencing the exact commit SHA.
15. Mapping 0 validator result referencing the same evidence.

## Fail-closed conditions

- A contract file is not schema evidence.
- A migration filename is not migration execution evidence.
- A guessed table/column name is not a mapping.
- A local mock database is not remote D1 evidence when remote D1 is required.
- A stale commit SHA invalidates the evidence.
- Missing expected-vs-actual output invalidates schema verification.
- Empty Evidence Registry fails the gate.
- Any unresolved entity/field mapping blocks promotion.

## AUTH feature checks

### AUTH-002

Session identity uniqueness, user isolation, expiration, revocation, required indexes and secret-derived material protection must be observed in the actual schema.

### AUTH-003

Username/email/phone canonical and normalized fields, deterministic normalization version, authoritative uniqueness and credential material protection must be observed in the actual schema.

### AUTH-004

Recovery challenge, purpose, derived token representation, expiry, consumption/invalidation state and session revocation linkage must be observed. Raw recovery tokens must be absent.

### AUTH-005

Verification challenge, identity/channel/purpose binding, derived token representation, expiry, single-use consumption and revocation state must be observed. Raw verification tokens must be absent.

### AUTH-006

Passkey owner, public key, RP binding, authenticator state and challenge lifecycle must be observed. Private keys must be absent from server persistence.

## Promotion sequence

`SCHEMA_CONTRACTED -> MIGRATION_EXECUTED -> SCHEMA_INSPECTED -> EXPECTED_ACTUAL_MATCHED -> SECURITY_SCHEMA_VERIFIED -> EVIDENCE_REGISTERED -> MAPPING0_VERIFIED`
