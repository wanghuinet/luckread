# AUTH-002–AUTH-006 Migration Gate v1.0

## Status

`CONTRACTED_NOT_VERIFIED / NOT_GREEN`

## Rule

No authentication persistence implementation may be considered complete until the migration is deterministic, executable, inspected against the intended D1 environment, and backed by evidence on the tested commit SHA.

## Required migration sequence

1. Resolve canonical entity and field authority.
2. Resolve exact D1 persistence owner.
3. Generate migration from the frozen contract; do not hand-infer fields during implementation.
4. Validate migration against an empty schema.
5. Validate migration against the expected pre-migration schema.
6. Execute migration in an isolated verification environment.
7. Inspect resulting schema and constraints.
8. Execute runtime persistence tests.
9. Execute negative/security/concurrency tests.
10. Capture Evidence Registry records.
11. Run Mapping 0 fail-closed validation.

## Feature gates

### AUTH-002
Session schema must prove unique session identity, user isolation, expiry/revocation state and required indexes.

### AUTH-003
Credential schema must prove deterministic normalized uniqueness for every enabled credential identifier and must not persist raw secret material.

### AUTH-004
Recovery schema must prove single-use, purpose-bound, time-bounded challenge state without raw token persistence.

### AUTH-005
Verification schema must prove single-use challenge consumption and identity/channel/purpose binding.

### AUTH-006
Passkey schema must prove credential ownership, public-key storage, RP binding and challenge lifecycle without private-key persistence.

## Non-negotiable failure conditions

- inferred column or index;
- duplicate canonical owner;
- migration without postcondition verification;
- schema evidence from an unrelated environment;
- evidence generated by a different commit than the tested runtime;
- successful test based only on mocks when real persistence is required;
- empty Evidence Registry accepted as success.

## Promotion

`MIGRATION_CONTRACTED` → `MIGRATION_EXECUTED` → `SCHEMA_VERIFIED` → `PERSISTENCE_VERIFIED` → `SECURITY_VERIFIED` → `MAPPING0_VERIFIED`.

Any missing stage keeps the feature non-green.
