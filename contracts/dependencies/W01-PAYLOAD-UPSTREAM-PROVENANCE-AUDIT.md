## Interpretation and required action

- Identical blobs are confirmed identical at the compared paths and commit.
- Modified files need classification. Configuration, LuckRead collections, and supported extension points can be legitimate; a diff alone cannot prove whether an upstream implementation was changed.
- W01-only files are not automatically violations. They include LuckRead product code, migrations, tests, local scripts, assets, and potentially copied/adapted code from other projects. Each reused source needs a traceable source URL/ref, license, copyright notice, and adaptation boundary.
- Upstream-only files are omissions at the compared paths, not proof of a problem.
- The current W01 tree is substantially evolved from the historical template. The result is therefore **not a clean bill of health** and must remain `REVIEW_REQUIRED` until the modified and copied-source classifications are completed.

The existing third-party notices already document the MIT-licensed `ccrsxx/twitter-clone` adaptations in two W01 frontend areas. Those notices should be retained and expanded if additional files from that project are identified.

This audit does not modify Payload source, remove D1 adapters, alter database configuration, or make a production migration decision. Reconcile the historical D1 template baseline with the current Neon target separately; do not restore obsolete upstream D1 runtime code.

Machine-readable counts and evidence are in `upstream-source-provenance.v1.json`.


## Classification of the 24 same-path differences

A focused source review of the key Payload integration files shows that the differences are in the template/application layer, not edits to the installed Payload package source:

| Files / group | Classification | Assessment |
|---|---|---|
| `.env.example`, `.gitignore`, `.npmrc`, `README.md`, `cloudflare-env.d.ts`, `eslint.config.mjs`, `next.config.ts`, `open-next.config.ts`, `playwright.config.ts`, `tsconfig.json`, `vitest.config.mts`, `wrangler.jsonc` | Project/runtime/tooling configuration | LuckRead-specific configuration; not Payload Core source |
| `src/payload.config.ts` | Payload official configuration/extension point | Uses `buildConfig`, official editor, storage and redirects plugin APIs, and a LuckRead-owned Neon adapter; replaces the template's D1 adapter configuration |
| `src/collections/Media.ts`, `src/collections/Users.ts` | Application-owned Payload Collections/hooks/access rules | LuckRead domain behavior built on Payload's collection APIs |
| `src/migrations/20250929_111647.json`, `src/migrations/20250929_111647.ts`, `src/migrations/index.ts` | Application database migration artifacts | LuckRead schema/migration records; not Payload package source |
| `src/payload-types.ts`, `src/app/(payload)/admin/importMap.js` | Generated Payload artifacts | Generated types/import map; should be regenerated by Payload tooling rather than treated as hand-maintained Core |
| `src/app/(frontend)/layout.tsx`, `src/app/(frontend)/styles.css` | LuckRead frontend application | Outside Payload Core |
| `src/app/(payload)/layout.tsx` | Payload-generated application route shell | File itself states it is generated; compare/regenerate through Payload CLI if drift matters |

**Result:** the reviewed differences do not show a modified Payload Core implementation or a private Payload fork. They show a heavily customized application/template integration using Payload configuration, Collections, hooks, plugins and generated artifacts. This is a bounded finding, not proof that every W01-only file is original or that every line of the 24 differences is compliant. The complete W01-only source provenance inventory remains open.

## Dependency configuration issue found during this review

W01's current `package.json` still lists `@payloadcms/db-d1-sqlite@3.90.2` in runtime `dependencies`, while `@payloadcms/db-postgres@3.90.2` is in `devDependencies`. The current `src/payload.config.ts` imports the LuckRead-owned Neon adapter rather than either official adapter directly, but this package placement is inconsistent with a clean Neon-only dependency inventory and requires a separate runtime/build-resolution review. **No package was removed or moved in this provenance task**, because doing so could affect build/runtime behavior and belongs to the W01 Neon closure task.

## Third-party source attribution

The two W01 `THIRD_PARTY_NOTICES.md` files explicitly identify MIT-licensed `ccrsxx/twitter-clone` UI adaptations and preserve the MIT copyright/permission text. One notice identifies the adapted tweet/thread presentation components; the other identifies the reused Tailwind/PostCSS/style/font and interaction-feed foundation. The notices also state that Firebase/Firestore backend logic is not reused. This is a documented attribution trail, but a file-by-file copied-source mapping and verification of the exact upstream license revision remain required for complete clearance.
